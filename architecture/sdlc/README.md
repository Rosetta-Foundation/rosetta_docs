# SDLC engine architecture

Reference documentation for the automated SDLC engine that lives in
[`rosetta_dev-scripts/sdlc-workflow`](https://github.com/Rosetta-Foundation/rosetta_dev-scripts/tree/main/sdlc-workflow).

These are **reference docs**, not decision records. An ADR says why a choice was
made and is immutable once accepted; these describe how the system currently
behaves and are expected to change as it does. Decisions that shaped the engine
live one directory up — most directly
[ADR-0008](../ADR-0008-implementation-spec-format.md) (the spec format the engine
consumes) and [ADR-0009](../ADR-0009-platform-boundary-mechanism-vs-policy.md)
(what the engine owns versus what a consumer repo owns).

## Reading order

If you are new to the engine, read [engine architecture](engine-architecture.md)
then [run lifecycle](run-lifecycle.md) — between them they explain the shape of
everything else. If you are operating a run that has stopped, go straight to
[run lifecycle](run-lifecycle.md#supervisor-exit-reasons) and then
[wake and escalation](wake-escalation.md). If you are onboarding a new repo to
the engine, [`.sdlc/` contracts](sdlc-contracts.md) is the only document you
strictly need. If you are about to optimize something, read
[performance baseline](performance-baseline.md) first — it records which two
plausible suspects were measured and found innocent. If you are cataloging
intake or shipping a same-day bundle, read
[work intake and ship verify](work-intake-and-ship-verify.md) — that document
is operator process in front of the engine, not a class-by-class source map.

## Scope and honesty

Every claim in these documents is traceable to engine source, and each document
cites the files it describes — except
[work intake and ship verify](work-intake-and-ship-verify.md), which is the
operator catalog / bundle / stakeholder-verify loop the drop command assumes. Where the engine's behaviour differs from the
aspiration recorded in a PRD, the reference document describes the engine and
says so explicitly — [agent roles](agent-roles.md) is mostly that distinction.

Diagrams are Mermaid, rendered inline by GitHub. They are generated by hand from
the source cited in each document rather than from the code itself, so they can
drift; treat the cited file as authoritative if the two disagree, and fix the
diagram.
