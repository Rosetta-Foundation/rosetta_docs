# PRD-0008: Local Workspace Folders

> A gitignored `local.json` override that lets engineers add personal folders to
> the generated `all.code-workspace` without polluting team config.

## 1. Overview & Goals

### 1.1 Purpose

`all.code-workspace` is generated by `team-setup update-config` from the checked-in
`shared.json`. This means personal folders (e.g. a private Chronicle repo, a
scratch directory, a personal queue file) cannot appear in the workspace without
either hand-editing the generated file (lost on next run) or adding the path to
`shared.json` (leaked to the entire team).

A gitignored `local.json` file provides a stable, regeneration-safe place to
declare personal workspace folders. `update-config` merges it with `shared.json`
at generation time so the output `all.code-workspace` includes both team and
personal folders.

### 1.2 Goals

- Allow any engineer to add personal folders to the generated workspace without modifying checked-in config.
- Survive regeneration: `update-config` always merges `local.json` into the output.
- Keep the interface minimal: one array of `{path, name?}` entries.
- Never leak personal paths into version control.

### 1.3 Non-Goals

- Not providing a GUI or interactive prompt for managing local folders.
- Not supporting local overrides of any other config (tracks, symlinks, etc.) — only additional workspace folders.
- Not supporting conditional inclusion (platform-specific, env-specific).

### 1.4 Acceptance Criteria

**Phase 1 — Local folder injection:**

- [x] A `local.json` file at `team-setup/src/config/local.json` is read by `update-config` when present.
- [x] Entries in `local.json` → `localFolders[]` are appended to the generated `all.code-workspace` after team folders but before the personal Chronicle folder.
- [x] `local.json` is in `.gitignore` — never committed.
- [x] If `local.json` is absent or malformed, `update-config` proceeds without error (graceful degradation).
- [x] Tests cover: local folders present, absent, malformed, and ordering in the output.

## 2. Users & Motivation

Serves any Rosetta engineer who has personal repos (private Chronicle), external
projects, or scratch folders they want visible in VS Code alongside the team
workspace — without maintaining a separate `.code-workspace` file or hand-editing
the generated one after every config refresh.

Immediate motivation: seeing `chronicles/queue.md` (PRD-0007) in the editor
requires the personal Chronicle repo in the workspace.

## 3. Approach

Add a single optional file to the config layer:

```
team-setup/src/config/
├── shared.json         ← team (checked in)
├── local.json          ← personal (gitignored)
└── tracks/
    └── default.json
```

`local.json` schema:

```json
{
  "localFolders": [
    { "path": "../my-personal-repo", "name": "Personal Chronicle" },
    { "path": "/absolute/path/to/scratch" }
  ]
}
```

Paths are relative to `baseDir` (same as all other workspace paths) or absolute.

The merge logic in `update-config`:
1. Load `shared.json` (required).
2. Load `local.json` (optional — if absent or unreadable, `localFolders = []`).
3. Pass `localFolders` through to `generateWorkspaceFile`.
4. Workspace folder order: shared → projects → flat → **local** → personal Chronicle.

Local folders are inserted before the personal Chronicle so the Chronicle (which
is always last) stays as the visual anchor at the bottom of the explorer.

## 4. Data Contracts

```ts
export interface LocalConfig {
  localFolders: LocalFolderEntry[];
}

export interface LocalFolderEntry {
  /** Relative to baseDir, or absolute. */
  path: string;
  /** Optional display name in VS Code. */
  name?: string;
}
```

## 5. Constraints & Dependencies

- **Architecture:** follows existing service pattern in `team-setup`.
- **Privacy:** `local.json` must be gitignored. The `.gitignore` entry must be committed with the feature.
- **Depends on:** existing `generateWorkspaceFile` in `workspace.service.ts`.
- **Backwards compatible:** no `local.json` = no change to output.

## 6. Risks & Open Questions

- **Path validation:** should `update-config` warn if a local folder path doesn't exist on disk? Probably yes (soft warning, not fatal), but deferring to keep Phase 1 minimal.
- **Schema validation:** if `local.json` has unexpected keys, should it error or silently ignore? Decision: silently ignore unknown keys; only fail on JSON parse errors (and even then, warn + skip).

## 7. Rollout & Phases

1. ✅ **Phase 1 — Local folder injection:** `local.json` support in `update-config` and `generateWorkspaceFile`, gitignore entry, tests, documentation in README.

## 8. Future Considerations

- **Local overrides for other config:** e.g. overriding `baseDir`, adding local symlinks, per-engineer track extensions.
- **Interactive setup:** `team-setup add-local-folder <path>` command that edits `local.json` for you.
- **Existence warnings:** soft warning when a declared local path doesn't exist on disk.
